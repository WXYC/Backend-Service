# PII field registry

The DJ-name family of columns spans two genuinely different kinds of data — a public on-air handle, and a legally-collected legal name — that have historically lived close enough together in the schema and the code to get confused with expensive consequences. This registry is the single place that states, per column, which kind it is, why it exists, where it's allowed to be read, and what (if anything) stops a new read site from leaking it. When adding a new column or read site anywhere near `real_name`/`dj_name`/`name`, check this table first.

## DJ name vs real name: a short history

Before commit `a0cd1979` (2025-12-31), the on-air handle and the legal name lived on two separate columns of the old `djs` table: `dj_name` (handle) and `real_name` (PII). That commit collapsed the table into `auth_user` and introduced `djName || name` fallback chains in the resolution code, while dj-site's admin provisioning flow began filling better-auth's required `name` field with `realName || username`. From that point on, `auth_user.name` — better-auth's innocuously-named, required display column — silently became a second, unmaintained copy of the legal name, and any ordinary `.name` read on a DJ row was a latent PII leak to a public surface: the flowsheet, the tubafrenzy mirror, wxyc.info. Several incidents (BS#1286, BS#1288, `2a37bbc6`, BS#1393, BS#2281) trace back to that one structural fact. `auth_user.name` is being converted back into a public-safe display value — the on-air handle if the DJ has one, else their username — via a derivation hook and a one-shot backfill (`jobs/auth-user-name-backfill`); until that backfill runs, treat any given row's `name` as untrustworthy for either purpose. This registry, the `COMMENT ON COLUMN` annotations in migration `0157_dj-name-pii-column-comments.sql`, and the `wxyc/restricted-real-name` ESLint rule exist to keep the two kinds of name from re-conflating.

## Enforcement

<!-- @rule id=real-name-restricted-lint enforced-by=eslint-rules/restricted-real-name.cjs added=2026-08-27 -->

**Reading `realName`/`real_name` outside an allow-listed file is a lint error.** Enforced by the `wxyc/restricted-real-name` ESLint rule (`eslint-rules/restricted-real-name.cjs`, registered in `eslint.config.mjs`, scoped to `apps/**/*.ts`, `shared/**/*.ts`, `jobs/**/*.ts`). Full rationale — the incident this closes, why both AST shapes are matched, why there's deliberately no `user.name` clause, the allow-list, and documented known gaps — lives in the rule's own docblock.
