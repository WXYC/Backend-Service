# Package reference

Per-package detail moved verbatim out of `CLAUDE.md`'s Monorepo Layout table. `CLAUDE.md` keeps a one-line row per package; this file holds the full text. Per-job detail lives in [`jobs.md`](jobs.md).

## `@wxyc/enrichment-worker`

Path: `apps/enrichment-worker/`

Long-running CDC consumer: claims new flowsheet track rows (`metadata_status='pending'`) and enriches via LML. N×N idempotent-claim (BS#892 / Epic C C2). C6 (BS#895) cron is the gap-recovery safety net. Track-context-gates every LML match on `isTrustedLmlTrackContextMatch` (BS#1359, refined BS#2217, `@wxyc/lml-client`) — `direct`/`compilation` auto-persist outright; a row-less `alternative` resolution (`library_item.id === 0`) also auto-persists when its title corresponds to the requested album, otherwise it and every other same-artist substitution route to the no-match arm. BS#1978: `ENRICHMENT_SUPPRESS_LML_BUDGET` (default off, `'live'` lane only) — see [`docs/env-vars.md`](env-vars.md).

## `@wxyc/database`

Path: `shared/database/`

Drizzle ORM schema, client, migrations, ETL utilities. One **subpath** export besides the barrel: `./streaming-merge-sql` (BS#2693), the shared streaming-column conflict-set SQL builders. It is a subpath and not a barrel re-export because the barrel re-exports `client.ts`, which throws at import time on missing DB env vars, and these builders must be importable — and `require`-able as compiled CJS by a `.spec.js` — without a database. Adding a subpath here takes the same four coordinated edits as `@wxyc/observability`'s `./metrics` (see the `@wxyc/observability` section below), plus `splitting: false`. Rationale, the drift guard on its locally-restated status union, and the reason a type-level assertion must not live in `tests/**` are all in that module's header — single home, don't restate them here.

## `@wxyc/lml-client`

Path: `shared/lml-client/`

HTTP client for library-metadata-lookup (LML). Single chokepoint — `lookupMetadata` wraps `Semaphore(5)` + `TokenBucket(50/min)` mirroring LML's Discogs ceilings (BS#906/G4). Used by `apps/backend` runtime path and `jobs/flowsheet-metadata-backfill`. Every caller-aware method is classified by a `caller`-keyed traffic-class policy (`caller` → class → timeout/budget; BS#1826) — see [`docs/env-vars.md`](env-vars.md#bslml-caller-classification-bs1826) + `shared/lml-client/src/policy.ts`. BS#1748: the runtime `defaultLimiter` bounds its pre-admission queue wait (`LML_LIMITER_MAX_QUEUE_WAIT_MS`, 5 s) and carries a **per-instance** circuit breaker (`circuit-breaker.ts`; never module scope — the BS#955 leak hazard) so a saturated LML fast-fails to the empty `GatedLookupResponse` shed shape (`outcome: 'shed_limiter_saturated'` / `'shed_breaker_open'`) instead of hanging; job limiters keep the unbounded shape.

## `@wxyc/observability`

Path: `shared/observability/`

Cross-container observability primitives, consumed by `apps/backend`, `apps/auth` and `apps/enrichment-worker` so every container applies byte-identical implementations. Package root: `redactQueryParams` / `redactLogValue` / `redactSentryEventQueryParams` / `redactSentryBreadcrumb` / `installConsoleRedaction` (BS#3054) — strip a failed Drizzle query's bound parameters (legal names since BS#3051) from the error logs of both apps and from backend's and auth's Sentry `beforeSend` and `beforeBreadcrumb`; see `docs/pii.md`. Also at the package root, `SENTRY_DATA_COLLECTION` (BS#3004) — the `dataCollection` option every app preload passes to `Sentry.init`, spelling out Sentry 10's no-options posture (no `userInfo`, so no end-user IPs; IP-bearing headers denied; no HTTP bodies) because Sentry 11 made all of them default-on and removed `sendDefaultPii`, which is now a silent no-op; every field must stay spelled out, since one left out falls back to the permissive default. Also at the package root, `warnIfReservedAwsCredentialsPresent` (BS#2532) — called right after `.env` loads in all three preloads (`apps/backend`, `apps/auth`, `apps/enrichment-worker`; backend and auth load it with `import 'dotenv/config'` as their first import, because ESM evaluates every import before a body-level `config()` and `@wxyc/lml-client` reads its limits at module load, BS#2949), warns once per process when `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` / `AWS_PROFILE` is set, the four names that top the SDK credential chain and shadow the EC2 instance role (BS#2518), matching `set-ec2-env-var.yml`'s deploy-time rejection list. It belongs at the ROOT, not a subpath: the preload is the only call site that runs in every container regardless of what the container goes on to do, and it stays barrel-safe by reading `process.env` and importing nothing. `./metrics` subpath (BS#2169): a generic buffered CloudWatch metric emitter (`createBufferedMetricEmitter` — buffer/coalesce/flush-on-interval-or-size/swallow-on-failure), extracted from the machinery duplicated between `apps/backend/middleware/responseMetrics.ts` (BS#845) and `apps/backend/services/sse/sse-metrics.ts`. Three consumers as of BS#2191, which finished the migration the extraction left undone: `apps/auth/auth-rate-limit-metrics.ts`, `responseMetrics.ts`, and `sse-metrics.ts`'s four counters — but NOT `sse-metrics.ts`'s `SSE/ClientCount` gauge, which is sampled rather than recorded, is not additive (the emitter coalesces by summing), and needs a companion emitted even at `total === 0`. Two coalescing invariants a new consumer depends on: `unit` is part of the coalesce key (same name + dimensions but different units are separate datums, never summed under whichever arrived first), and the companion setting is rank-merged across a coalesced group rather than first-wins. **`emitDimensionlessCompanion: 'perEntry'` (= `true`, N + N) and `'aggregated'` (N + 1 summed across slices) agree only under `Sum`** — switching a live metric between them silently rescales every Average/Maximum/SampleCount alarm on it. `flushIntervalMs: null` (caller owns the cadence) and `logPrefix` exist for the same reason: a migrated call site's published shape or log grep depended on them. `flush()` joins any in-flight size-triggered send rather than resolving early against the already-drained buffer — that is the contract `apps/auth`'s SIGTERM handler depends on, since the flush timer is `unref`'d on a 30 s interval and a deploy would otherwise drop a full window. Also exports `createCloudWatchClient` (BS#2533) — the fleet's ONLY `new CloudWatchClient(...)`, pinned to `credentials: fromInstanceMetadata()` so a stray `AWS_ACCESS_KEY_ID` can't outrank the `wxyc-ec2-backend` instance role the way the SES credential did for 105 days in BS#2518; `sse-metrics.ts`'s gauge keeps its own client INSTANCE but builds it through that function, and `tests/unit/observability/cloudwatch-credentials.test.ts` fails if a second construction site appears. The corollary is that nothing off EC2 can publish, so all three opt-out env vars are now actually set in the compose profiles, the GHA workflow and `.env.example` rather than merely recommended in `docs/env-vars.md`. **The `./metrics` subpath is a deliberate second tsup entry, never re-exported from the barrel** (`src/index.ts`) — re-exporting an AWS-SDK-backed emitter from the barrel would eagerly load `@aws-sdk/client-cloudwatch` at process preload in every image that loads the barrel. `./job-logger` subpath (BS#3397): `createJobLogger({ jobName })`, the shared logger for the cron and one-shot jobs under `jobs/` (Sentry init with the run-wide `repo` / `tool` / `run_id` tags, JSON log lines, and captures routed through an `ErrorReporter`); `jobName` keys the `captureWarning` fingerprint, and `closeLogger` awaits `reporter.flush(2000)` before `Sentry.close(2000)`. `initLogger` registers its reporter with `setErrorReporter` right after `Sentry.init`, so a job registers through `createJobLogger` and shared-library captures via `getErrorReporter()` reach it (BS#3501). Piloted on `jobs/legacy-linkage-resolve`, which replaced its own `logger.ts`. `Sentry.init` and the run-wide tags stay in it, imported from `@sentry/node`, until slice B9 of BS#3393, because the reporter seam has no method for them. `./posthog` subpath (BS#3407): `PostHogReporter`, an `ErrorReporter` over `posthog-node` that sends `$exception` events to the PostHog "Services" project, following WXYC/wiki `patterns/error-tracking.md`. Constructor `{ service, environment, release, budget, properties }`: `environment` is the raw `NODE_ENV`, mapped to production/staging/development with unset or unknown as production; `budget` is `{ kind: 'daily', ceiling }` (capacity 20, refill ceiling / 86,400 per second) for long-running processes or `{ kind: 'run', ceiling }` (capacity = ceiling, no refill) for scheduled runs; `properties` carries the job logger's run-wide `repo` / `tool` / `run_id`. No `POSTHOG_ERRORS_API_KEY` means every call is a no-op. `captureMessage` sends a synthesized `$exception` (`Message` entry, `$exception_types: ['Message']`); fingerprint parts are joined with `:` into the single-string `$exception_fingerprint`; `$exception_level` is passed on the exception path only when it is `warning`, because posthog-node sets `error` itself. A 60 s same-fingerprint dedupe runs before the token bucket. Breadcrumbs (last 50) and request tags live in a scope: `runInScope(fn)` opens one per request. Outside a scope `setRequestTag` is a no-op (warned once per process) and breadcrumbs go to a small bounded process-level ring for single-flow jobs, so an HTTP app that registers this reporter must wrap each request in `runInScope` (BS#3409 wires that middleware) or its request tags are dropped. Exceptions, messages, breadcrumbs and `extra` pass through `redactQueryParams` / `redactLogValue`. It must never be re-exported from the barrel (that would load posthog-node in every image). Adding a subpath here needs four coordinated edits, not just the `exports` map: a tsup `entry` array addition, a tsup `external` addition for the subpath's own third-party deps, a `jest.unit.config.ts` `moduleNameMapper` entry (the bare-specifier mapping does not also match a subpath), and a `tests/tsconfig.json` `paths` entry (ts-jest's `moduleResolution: "Node"` ignores `exports` maps entirely, unlike the apps' own `bundler` resolution).

Also at the package root, the `ErrorReporter` seam (BS#3394/BS#3395): the `ErrorReporter` interface, `CompositeReporter`, `logCounter` (the one counter API: counters are log lines, not reports, so the `ErrorReporter` interface has no counter method and a `CompositeReporter` never fans one out; a job's `captureCounter` calls it with the run's `repo`/`tool`/`run_id`), and the process-wide holder `setErrorReporter` / `getErrorReporter`. An app registers its reporter once at startup, next to its SDK init; call sites resolve it with `getErrorReporter()` per call, never at import time. Until something registers, the holder returns a no-op reporter, so a library used before any app wiring never throws. The holder lives on `globalThis` under `Symbol.for('@wxyc/observability/error-reporter')`, not in a module-local variable, so every loaded copy of the package shares one slot — including a library that resolves the CJS build while its app registered through the ESM build (the `@wxyc/authentication` case, BS#3396). `./sentry` subpath: `SentryReporter`, the `ErrorReporter` over `@sentry/node`. It is a separate tsup entry and never re-exported from the barrel, for the same reason as `./metrics`: the barrel loads at preload in every image, and must not eagerly load `@sentry/node` through it. `apps/auth`, `apps/enrichment-worker` and `shared/authentication` report through it too (BS#3396): both preloads call `setErrorReporter(new SentryReporter())` right after `Sentry.init`, and `@wxyc/authentication` depends on `@wxyc/observability`, so the root `build`, `lint:prebuild`, `predev` and `Dockerfile.deploy-builder` build `@wxyc/observability` before the other `shared/**` packages. `apps/auth`'s `fallbackErrorHandler` keeps its unconditional capture (BS#1221/BS#1109). **Dual-run (BS#3409):** each app preload and `createJobLogger` register `CompositeReporter([SentryReporter, PostHogReporter])` (services `backend` 300/day, `auth` 100, `enrichment-worker` 100, a job its name with a per-run `errorBudget` of 10, or 2 for the two jobs that run more than 4 times a day; `release` from `SENTRY_RELEASE`, `environment` from raw `NODE_ENV`). `ErrorReporter.runInScope?` is the one optional seam member; `CompositeReporter` nests it through each child that has it and `SentryReporter` does not, and `requestScopeMiddleware` (backend and auth, after the body parser and before `requestIdMiddleware`) calls it, falling back to calling `next` directly. Sentry's `expressIntegration` already captures Express errors, so `createExpressErrorMiddleware` (before each app's error handler) reports to a separate `setExpressErrorReporter` slot holding the PostHog reporter alone, under the same predicate Sentry gets, attaching only `request_id`, route template, method and status (BS#3004). Shutdown awaits `getErrorReporter().flush(2000)` in all three apps.

## Database (`shared/database`) notes

**Correlated select fields:** inside a select-field `sql` fragment, reference the outer row's column only through `outerRef(column)` (`apps/backend/utils/sql-fragments.ts`). A bare column in a single-table select renders unqualified and binds to the subquery's own table, silently.
