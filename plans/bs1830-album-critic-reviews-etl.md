# BS#1830 — `jobs/album-critic-reviews-etl`: manifest → library-matched `album_critic_reviews` (weekly cron)

## Context

`album_critic_reviews` (migration 0125, ADR 0012) was seeded once, manually, via `scripts/seed-critic-reviews.ts` on 2026-07-26 (~1,823 rows from a 4-source corpus). There is no recurring pipeline. This plan builds the weekly cron the epic (#1718) listed as its follow-on.

Both code-level dependencies are closed/merged: `resolveLinkedAlbumId` now lives in `@wxyc/database` (`shared/database/src/album-resolve.ts`, BS#1829/PR#1831), and `WXYC/research-data#1` (crawl + manifest publish) is merged — `build_manifest.py` and `crawl.yml` are committed there, publishing a `manifest-latest` release with a single `manifest.jsonl.gz` asset.

**Pre-flight gap (verified during this planning pass, not just quoted from the issue):** `gh release view manifest-latest` (run against `WXYC/research-data`, confirmed private via `gh repo view`) returns `release not found`. `crawl.yml`'s only trigger before the monthly `0 8 1 * *` cron is a manual `workflow_dispatch`. **This PR does not trigger that workflow** — dispatching a cross-repo crawl (up to a 360-minute budget, scraping ~9 external sites) is a side-effecting action on a different repo, out of scope for a code PR, and explicitly framed in the issue as a separate operational step ("someone must..."). Consequence: the two acceptance-criteria items that require a _real_ published manifest (real-manifest DRY_RUN report with per-source counts; the `GET /proxy/metadata/album` end-to-end check) cannot be closed by this PR alone. Everything else — including the full unit-test suite, the fetch path exercised against a hand-built manifest fixture, and every other acceptance-criteria item — is in scope and will be closed here. The PR description will call this out explicitly rather than silently claiming full closure.

## Manifest contract (verified against `WXYC/research-data` source, not just the issue's quoted table)

Read `build_manifest.py` and `crawl.yml` directly:

```jsonc
// One line per CorpusItem in manifest.jsonl (gzipped as manifest.jsonl.gz)
{
  "artist": "string, required",
  "album": "string, required (raw, undecorated)",
  "source": "string, required — display name e.g. 'The Quietus'",
  "sourceUrl": "string, required",
  "articleText": "string, required — full article text",
  "author": "string, optional (omitted, not null, when absent)",
  "publishedAt": "string, optional (omitted when absent)",
  // NOT emitted by build_manifest.py today: "rating", "discogsReleaseId".
  // Keep both on the CorpusItem TS type anyway (issue's explicit instruction —
  // the seed script's toRow already reads them) so a future manifest revision
  // that adds them needs no ETL-side type change; today they fall through to null.
}
```

Current `SOURCES` list in `build_manifest.py` (display names — what `source` will contain): `The Quietus`, `Tiny Mix Tapes`, `Bandcamp Daily`, `HHV Mag`, `Paste`, `Beats Per Minute`, `A Closer Listen`, `The Line of Best Fit`, `Drowned in Sound`. This is the _upstream_ source of truth; the ETL's ranking table (below) is independent data the ETL owns, not derived from this list, so a 10th upstream source needs zero ETL code change (it lands in the deterministic fallback tail automatically — see Dedup below).

The release is fetched via GitHub's REST API (private repo): `GET /repos/WXYC/research-data/releases/tags/manifest-latest` → find the `manifest.jsonl.gz` asset → `GET` its `url` (the API asset endpoint, not `browser_download_url`) with `Accept: application/octet-stream` and the same bearer token. No LFS, no repo clone.

## Pipeline shape (`orchestrate.ts::runEtl`)

1. **Fetch + gunzip + parse.** Empty response (0 bytes / 0 lines) → throw (source regression, mirrors donor's empty-sheet guard).
2. **Validate.** `parseManifestLines` → `{items, invalid}`. Guard: `items.length === 0` → throw.
3. **Match.** `matchItem` per item (exact match + decoration-strip fallback). Build `matched: {item, albumId}[]` (only non-null resolutions).
4. **Guard: `matched.length === 0` → throw.** (Evaluated regardless of DRY_RUN — a regression in the resolver, or a corpus gone stale against the library, must not hide behind a dry run.)
5. **Dedup.** `dedupeByAlbum(matched)` → one `{item, albumId}` per distinct `albumId`, chosen by `compareSourcePreference`. Tally `matched_by_source` from the deduped set (this is what the issue's "Quietus 880 / TMT 736 / Bandcamp 207" seed-run breakdown measures — post-dedup, sums to `matched`).
6. **Anti-join.** `loadExistingPairs` for the deduped `albumId`s, `filterNew` → `newItems`. Tally `already_present = deduped.length - newItems.length`.
7. **DRY_RUN → emit locked JSON report, return.** Zero Anthropic calls (never reaches step 8), zero writes. Report shape (new, job-specific — not the donor's literal schema):
   ```json
   {
     "job": "album-critic-reviews-etl",
     "dry_run": true,
     "fetched": 0,
     "parsed": 0,
     "invalid": 0,
     "matched": 0,
     "matched_by_source": {},
     "already_present": 0,
     "would_extract": 0
   }
   ```
8. **Extract + write.** For each `newItem`: `llmExtract` (per-item try/catch — a single poisoned item must not wedge the run; caught errors counted + Sentry-deduped, same idiom as the donor's per-row upsert errors), `buildRow` (returns `null` on `isReview:false` or an unfittable snippet → counted as `rejected`, never thrown), `upsertRow` for a built row (counts `inserted`/`updated`/`unchanged`).
9. **Guard: `newItems.length > 0 && written === 0` → throw** (donor's "valid rows mapped but 0 written" shape — a wholesale extraction/write regression must not report a green run).
10. **`newItems.length === 0`** (steady-state, everything already anti-joined) logs a distinct `nothing_new` step line, so a healthy no-op weekly run is visible in logs as "checked, nothing to do" rather than indistinguishable from a run that silently skipped work.
11. Log + return full `Totals`.

`Totals` (real-run superset of the DRY_RUN report): adds `extracted`, `rejected`, `llm_errors`, `inserted`, `updated`, `unchanged`, `written` (`= inserted + updated + unchanged`).

## Key design decisions worth flagging explicitly (for plan review)

1. **Author precedence reversed from the seed script** (see `extract.ts` above) — the issue is explicit about this; a straight port of `toRow` would be wrong here.
2. **No transient-fetch retry** for the GitHub API calls. The donor's `withSheetRetry` (BS#1692) was a _later_ hardening pass on `album-reviews-etl`, not part of its original shape, and the issue doesn't ask for one here. A failed weekly run is cheap to re-trigger manually or simply waits a week; adding a bespoke retry wrapper for a two-call GitHub API sequence is scope the issue didn't request. Flagging so a reviewer can push back if they'd rather have it now.
3. **No explicit `ANALYZE` statement.** The issue cites `docs/bulk-update-playbook.md` but immediately qualifies it — "batching mostly matters if a big corpus drop lands" — and the playbook's actual concern (stale planner stats defeating an index on a heavily-queried table like `flowsheet`) doesn't apply to a brand-new, lightly-written, `album_id`-PK-indexed table with no autovacuum history to go stale. Sequential per-row UPSERTs (matching the manual seed run and the donor's per-row writer) are proposed as sufficient; no batching/ANALYZE code added.
4. **REVISED during implementation: anti-join uses `db.execute(sql\`...\`)`raw SQL with the`{1,2,3}::int[]`literal idiom from`library-tiebreak.ts`, not drizzle's `inArray()`query-builder helper.** The plan originally proposed`inArray()` to sidestep the int-array-literal dance entirely. Implementing against the shared test mock (`tests/mocks/database.mock.ts`) surfaced why the donor (`jobs/album-reviews-etl/link.ts`) doesn't do that: `createMockQueryChain`'s chain methods (`select`/`from`/`where`/`limit`) are all synchronous (`mockReturnValue(chain)`) — only `.returning()`and`.execute()`resolve to a value. A bare`await db.select().from(t).where(inArray(...))`is awaitable in REAL drizzle (its query builder is itself thenable) but resolves to the mock chain object itself under the shared mock, not an array — unusable in a unit test.`db.execute(sql\`...\`)` is the one shape the shared mock actually terminates, and it's the donor's own established idiom for exactly this kind of read. Switched to match it.
5. **`ANTHROPIC_API_KEY` required only when `!dryRun`** (mirrors the seed script's `SKIP_LLM` fail-fast gating, adapted since this job has no `SKIP_LLM` toggle — DRY_RUN subsumes that role per the issue). `RESEARCH_DATA_TOKEN` is required unconditionally — DRY_RUN still needs the real manifest.
6. **Decoration-strip retry only fires when the stripped title differs from the original** — avoids a redundant second `resolveLinkedAlbumId` call (and thus a redundant DB round-trip) for the common case where the album title carries no edition suffix.
7. **The expansion-source ranking (Line of Best Fit → Drowned in Sound → Paste → Beats Per Minute → A Closer Listen → HHV Mag) is explicitly a "Proposed" judgment call per the issue** — "confirm with the music director / editorial before merge." This plan implements it as the working default (it's plain data in `RANKED_SOURCES`, a one-line edit either way) but treats it as UNCONFIRMED pending sign-off; the PR description will call this out as an open item rather than a settled decision, and the editorial head (Quietus → TMT → Bandcamp) — which is NOT a proposal, it's carried over from the seed era — is unaffected either way.

## Tests (`tests/unit/jobs/album-critic-reviews-etl/`)

- `manifest.test.ts` — valid line round-trip; missing/empty required field per field; malformed JSON; optional fields fall through to absent/undefined, not null-coerced.
- `match.test.ts` — `stripAlbumDecoration`: each keyword (reissue/deluxe/remaster/remastered/expanded/ep/deluxe edition) case-insensitively, no-op when no trailing parenthetical, no-op when the parenthetical isn't an edition clause (e.g. `(Live)` — preserved, distinct from `normalizeAlbumTitle`'s broader stripping which this deliberately does NOT reuse, since the issue calls for a narrow literal port, not the broader free-text normalizer). `matchItem`: exact hit skips the fallback call entirely (mock call-count assertion); miss-then-fallback-hit; miss-then-fallback-miss; fallback skipped entirely when stripping is a no-op (call-count assertion).
- `dedup.test.ts` — `compareSourcePreference` pins the full ranked order; **the recall-bug guard**: an unranked source is the sole candidate for an album → still wins (explicit test, per the issue's acceptance criteria); two unranked sources tie-break alphabetically case-insensitively; a ranked source always beats an unranked one regardless of manifest order.
- `antijoin.test.ts` — `filterNew` pure-logic cases; `loadExistingPairs` result-shape handling (array result, `{rows}` result, unrecognized-shape throw) via the mocked `db.execute`.
- `extract.test.ts` — snippet cap/boundary trim (reuse the seed script's existing case shapes: exact-fit, sentence-boundary cut, word-boundary fallback, reject-when-neither-boundary-clears-60%); `isReview:false` → null row; **author precedence**: manifest `author` present + LLM `author` present → manifest wins (the reversed-precedence pin from design decision #1); manifest absent + LLM present → LLM wins; both absent → null.
- `writer.test.ts` — mirrors the donor's `writer.test.ts` structure: conflict target `(album_id, source_url)`, `set`/`setWhere` derived from one column list (single source of truth, same anti-drift idiom), `xmax` insert/update/unchanged.
- `orchestrate.test.ts` — zero-parsed throws; zero-matched throws (dry and non-dry); DRY_RUN report shape + zero `llmExtract`/`upsertRow` calls; anti-join skip counts; real run with a mix of new/already-present/rejected/error items; zero-written-when-new-existed throws; **end-to-end unranked-source recall case** (an album whose sole matched review is from an unranked source still appears in `newItems` and gets written — the acceptance criterion's explicit ask, exercised at the orchestrator level in addition to the unit-level `dedup.test.ts` pin).
